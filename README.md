# Практична робота №5 — SPA


## Перевірка в DevTools

1. Натиснути F12 → вкладка Network → фільтр Doc.
2. Увімкнути музику і поклацати по розділах.
3. У списку тільки один запит — `index.html`. Нових сторінок браузер не завантажує, музика і таймер працюють далі.

## Відповіді на запитання

**1. Чим відрізняється MPA від SPA при переході?**
У MPA кожен клік завантажує нову сторінку з сервера, і стара повністю зникає. У SPA сторінка завантажується один раз, а JS просто показує інший розділ.

**2. Що видно в Network?**
У MPA на кожен перехід з'являється новий запит за HTML. У SPA запит є тільки один, при першому відкритті. Далі змінюється лише `#` в адресі.

**3. Чому в MPA все скидається?**
Змінні, таймери і музика живуть усередині сторінки. Коли браузер відкриває нову сторінку, стара видаляється разом з усім цим.

**4. SPA проти SSR і SSG?**
- SPA: переходи швидкі, але перше відкриття повільніше, і пошуковики гірше бачать вміст.
- SSR: сервер одразу віддає готову сторінку. Швидко відкривається і добре для пошуку, але сервер більше навантажений.
- SSG: сторінки створюються заздалегідь. Найшвидше і добре для пошуку, але не підходить для даних, які часто змінюються.

**5. Що таке гідратація?**
Сервер віддає готовий HTML, його одразу видно, але кнопки ще не працюють. Потім завантажується JS і «оживляє» сторінку: підключає кліки та інші події.

## Висновок

Я зробив односторінковий сайт на чистому JavaScript. Розділи перемикаються через зміну `#` в адресі, без перезавантаження. Плеєр і таймер у шапці показують, що стан зберігається: музика не зупиняється, таймер не скидається. У Network видно лише один запит за сторінкою, отже переходи відбуваються на стороні браузера.
